# 2. 要解決的問題
電腦記憶體不夠用,通常是因為瀏覽器開了太多網站分頁。很多分頁當下用不到,卻一直占著記憶體。

# 3. 核心解法(我已決定,請不要換掉)
當我暫時不需要某個網站時,我按一下擴充功能,它會:
1. 把這個網頁的網址(與標題、圖示)儲存到擴充功能裡
2. 關閉這個分頁,釋放它占用的記憶體
3. 之後我想用的時候,可以從擴充功能裡一鍵把它重新開啟

# 4. 開始前先做調查(寫入 RESEARCH.md,不超過 30 分鐘)
- 查找現有的同類擴充功能(例如 OneTab 一類)與 Chrome 內建的記憶體節省功能,列出各自的優缺點與使用者常見抱怨(特別留意「資料遺失」「卡頓」「權限過大」類的評論)
- 找出本專案可以做得更好的 2 到 3 個差異點並說明選擇理由,寫入 DECISIONS.md。我傾向的方向是:以「存起目前這一個分頁」為最順手的操作、資料保存特別安全、還原體驗特別好;你可以提出更好的建議,但要說明理由
- 查證目前 Manifest V3 的限制、儲存配額與官方最佳實踐,以官方文件為準,不要憑記憶

# 5. 【新增】架構與資料安全(整個專案最重要的工程原則)
## 5.1 先寫後關(最高優先)
存入分頁時,流程必須是:收集分頁資訊 → 寫入儲存空間 → **讀回驗證寫入成功** → 才關閉分頁。任何一步失敗,就不要關分頁,並明確告訴使用者原因。批次存入要做到「全部成功或全部不關」,或逐筆確認成功後才關該筆,並在介面誠實顯示結果(例如「Saved 7 of 8 tabs. 1 could not be saved.」)。
## 5.2 資料模型
- 設計清楚的資料結構:條目 id、url、title、favicon 資訊、存入時間、來源視窗資訊、分組與標籤、狀態
- 每筆資料與整個資料庫都帶 schema 版本號,並實作版本遷移機制,日後改結構不會弄壞舊資料
- 偵測資料毀損,毀損時不要靜默清空:提示使用者並提供匯出現有資料與復原選項
## 5.3 儲存策略
- 自行評估 chrome.storage.local 與 IndexedDB 的容量、效能與可靠性後選擇並說明;若需要較大容量,評估是否需要 unlimitedStorage 權限並說明利弊
- 自動滾動備份:保留最近 N 份本機快照(例如每次大量變更前),可在設定頁還原
## 5.4 Service Worker 注意事項
Manifest V3 的 service worker 隨時會被回收:不得依賴常駐記憶體狀態;所有狀態都要能從儲存空間重建;事件監聽器必須在最上層同步註冊。
## 5.5 模組切分
把「與瀏覽器 API 綁定的部分」與「純邏輯(去重、搜尋、分組、匯入匯出、資料遷移)」分開,純邏輯必須可以脫離瀏覽器單元測試。
## 5.6 權限策略
權限最小化,逐一在 README 說明用途。需要「偵測頁面有沒有未儲存輸入」這類能力時,評估它是否需要對所有網站的讀取權限;若會讓權限變得過大,就不要做,改用保守的通用提醒,並把取捨寫進 DECISIONS.md。優先使用 activeTab 與執行時才請求的選用權限。

# 6. 功能清單與驗收標準
標 ★ 的是核心閉環,時間再緊也必須保住。

## P0:必須全部完整可用
1. ★ 一鍵存起並關閉目前分頁:點擴充功能圖示即可完成,有清楚的視覺回饋(簡短動畫與已存數量)
2. ★ 已存分頁清單:彈出視窗與獨立完整頁面都能看,每筆顯示網站圖示、標題、網址、存入時間
3. ★ 一鍵還原:單筆還原、全部還原;設定「還原後是否從清單移除」(預設移除)
4. ★ 【新增】存入後的「復原(Undo)」:存入後數秒內可在提示中按 Undo,把剛關掉的分頁重新開啟並從清單移除該筆
5. 特殊分頁處理(每種都要實測並寫入 TEST_REPORT.md):
   - 瀏覽器內部頁面(例如 chrome:// 開頭)無法正常還原:明確提示並略過,不可出錯
   - 釘選分頁:預設不關閉並說明原因
   - 正在播放音訊或影片的分頁:存入前跳出確認
   - 可能有未儲存內容的分頁:依 5.6 的結論提醒使用者
   - 重複網址:自動偵測,避免重複存入並提示
   - 無痕視窗:依權限狀況正確處理並說明
   - 一個視窗只剩最後一個分頁時存入:不能讓視窗意外消失造成混亂,要有妥善處理並說明
6. 存入範圍三種模式:目前分頁、目前視窗中除了目前這個以外的分頁、目前視窗全部分頁
7. 搜尋與刪除:即時搜尋標題與網址;單筆刪除;清空全部(需二次確認)
8. 匯出與匯入(JSON):匯入要處理重複、格式錯誤與版本差異,並顯示結果摘要
9. 設定頁:還原後是否移除、預設存入範圍、深色模式、備份還原
10. 【新增】首次使用引導:安裝後第一次開啟顯示簡短說明(3 步以內),可跳過,之後不再顯示
11. 基礎品質:完整的 empty / loading / error 狀態;鍵盤可操作;顏色對比足夠;尊重減少動態偏好(prefers-reduced-motion);內建「Load demo data」按鈕可一鍵填入示範資料

## P1:P0 驗收通過後做(請盡量全做)
1. 快捷鍵:可自訂,一鍵存起目前分頁
2. 右鍵選單:在網頁或分頁上按右鍵即可存起
3. 分組與標籤:可自行分組(例如「Work」「Read later」),整組還原
4. 白名單:指定網站永不被關閉或存入
5. 統計頁:累計存起的分頁數,以及「估計」釋放的記憶體(必須標示為估計值並說明估算方式,不得誇大)
6. 還原到原本視窗並盡量恢復順序
7. 【新增】徽章顯示已存數量(圖示上的小數字)
8. 【新增】還原時的記憶體保護:一次還原大量分頁時,提示數量並讓使用者選擇「分批開啟」,避免剛省下的記憶體又被瞬間吃光

## P2:加分創意區(由你自行挑 2 到 3 個,並在 DECISIONS.md 說明價值與成本)
候選,你可以換成更好的:
- 休眠模式:不關閉分頁,而用瀏覽器提供的機制讓分頁釋放記憶體(分頁留在原位,點回去才重新載入),與「存起並關閉」並存讓使用者選擇
- 自動處理久未使用的分頁:可設定閒置多久,並有保護機制(白名單、播放中、釘選都不處理)
- 記憶體占用視覺化:顯示各分頁相對耗用,僅限瀏覽器開放足夠能力時;做不到就如實說明並刪除
- 【新增】匯入常見的「網址 | 標題」純文字清單格式(其他同類工具常用的匯出格式,請自行查證格式),方便從舊工具遷移
- 稍後提醒:為已存分頁設定提醒時間並通知
- 跨裝置同步:在容量限制內,並明確處理超出配額的情況
- 你有更好的點子也歡迎

# 7. 視覺與動態設計規範
- 先做設計研究:參考優秀的瀏覽器擴充功能與生產力工具介面,以及設計獎站與設計社群的案例。把參考了哪些、學到什麼寫進 DESIGN.md。只借鏡手法,不可複製他人的素材、文案或程式碼。
- 不要有「AI 範本感」:避免無個性的紫藍漸層、到處用 emoji 當圖示、千篇一律的卡片版型、預設字體加預設圓角。
- 建立自己的設計系統:色彩 tokens、字體、間距、圖示風格統一;圖示自行繪製或使用可商用的素材。
- 動態效果:存入時的收進動畫、還原時的展開、清單進出場、按鈕微互動;有節奏與緩動(spring/ease),不要單調淡入淡出。
- 彈出視窗尺寸有限,資訊密度與易讀性要平衡;最重要的操作(存起並關閉)一眼就看到、一按就完成;彈出視窗開啟要立刻有內容。
- 【新增】擴充功能圖示的設計:需要 16/32/48/128 各尺寸,在淺色與深色瀏覽器主題下都清楚;並設計「已有存入項目」的圖示狀態。

# 9. 隱私與安全
- 不連外部伺服器、不收集使用資料、不含第三方追蹤腳本;資料只存在使用者本機
- 內容安全政策嚴格,不使用 eval,不載入遠端程式碼
- 顯示他人網頁標題與網址時,一律當作不可信的文字處理,避免注入問題
- 【新增】在 README 與設定頁提供清楚的「Where is my data stored?」說明,以及一鍵匯出與一鍵清除全部資料

# 10. 驗收測試(實際執行並寫入 TEST_REPORT.md)
- 端到端:開啟多個不同網站分頁 → 存起並關閉 → 清單出現 → 還原 → 分頁重新開啟且內容正確

- 【新增】故障注入測試:模擬寫入失敗,確認分頁不會被關閉;模擬 service worker 被回收後再操作,確認資料不遺失

- 大量資料:存入 1000 筆,清單與搜尋仍流暢
